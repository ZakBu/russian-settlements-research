# Национальная выборка опубликованных физических мест

Источник: **Overture Maps Places, release2026-09-23.1**, установлен по первичному STAC19.10.2026. Обработаны метаданные **всех16 мировых GeoParquet-файлов**, всего81 455 423 исходных строк и10 996 226 026байт. Целиком мировой массив не скачивался. Получено **648 242 строк** территориальной выборки; это не количество всех учреждений России и не количество доказанных центров обслуживания.

## Получение, схема и воспроизведение

1. `acquire_overture.py` получает STAC и список S3-объектов. Для каждого файла читаются последние8байт и footer, схема и статистики пространственных групп строк. Сменаreleaseвсуществующемnamespaceзапрещена.
2. `extract_ru_places.py` отбирает пересекающиеся группы по широкой рамке19…180°в.д./41…83°с.ш. и западной стороне линии перемены дат≤−168°/≥60°. Вначале скачиваются только `bbox` и `addresses.country`. Затем читаются атрибуты групп, где есть `country=RU` либо попадание в coarseNaturalEarthRUSpolygon. Это два разных признака, сохранённых раздельно. Рамка и полигон — инструмент отбора, не юридическое установление границ.
3. Второй проход получает только11верхних полей: `id`, `geometry`, `confidence`, `addresses`, `names`, `sources`, `operating_status`, `basic_category`, `taxonomy`, `version`, `bbox`. Старая `categories` в этой версии уже удалена; новая схема проверена до загрузки. Выбраны648242строк;648242 — не один только источниковыйcountryRU.
4. Каждый полученный диапазон проверяется по HTTP206, точному Content-Range, длине иSHA256. Сохранены footer, схема, row-groupbounds, URL, ETag и записи диапазонов. Полный SHAнескачанных мировых файлов **не заявляется**. Воспроизводится выбранная таблица, не провайдерская исходная консолидация.

```bash
python national_integration_20261019/places/acquire_overture.py --release 2026-09-23.1
python national_integration_20261019/places/extract_ru_places.py
python national_integration_20261019/places/build_places_features.py
python national_integration_20261019/places/validate_places.py
```

НужныPython,pyarrow,pandas,numpy,scipy,matplotlib; дляполучения — обычныйurllib. Асинхронный клиент получилproxy403; штатныйurllibмаршрут работал с206. Ошибки сохранены в `metadata/failed_operations.jsonl`, а доступная S3/Azureальтернатива не объявлена отсутствующей.

Текущие выбранные атрибуты требуют243883614байт успешных уникальных диапазонов данных. Повторное получение одного повреждённого локального derivativeпотребовало ещё51308775байт; footer/неудачные сетевые ответы учитываются отдельно, это не точный счётчик всего сетевого трафика. Дефект00014сохранён в `LOCAL_ARTIFACT_RECOVERY.json` и `.corrupt_preserved`; исходные S3байты не изменены. Восстановленный фрагмент прошёл полный холодный readback иSHA; затем холодно перечитаны все7созданных Parquet(остальные9мировых файлов отсечены footer). Запись новых таблиц выполняется атомарно послеfsyncиобратногочтения.

## Связка с неизменной осью

`places_settlement_features.parquet` содержит **142570непустых уникальных `id`**, по одной строке для всей исходной оси. Окончательные численности и проверки находятся в `AUDIT.json` и `VALIDATION.json`; полное присутствие оси не означает содержательного покрытия всехНП.

- `baseline`: буквальное нормализованное имя `addresses.locality` соответствует ровно одному НП среди **всех одноимённых** в10км, расстояние до него≤5км, нет странового конфликта. РегистрацияНП и внешняя центральность этим не устанавливаются. Произвольный ближайший пункт не может статьbaseline.
- `conditional`: единственное адресное имя при5…10км/страновом конфликте либо имя с явным типомНП в свободной адресной строке при≤5км. Это **дополнительные объекты**, неbaselineвместе с ними. Полная альтернативная версия требуетbaselineORconditional.
- `nearest_candidate`: отдельный географический кандидат≤10км для оставшихся записей. Ближайший диагностическийUID и расстояние также сохранены у остальных объектов; их нельзя использовать без проверки `source_geography_scope` и странового конфликта. Даже точный адрес объекта не задаёт обслуживаемое окружение.

География вне конкретной оси не распределяется по деревням: явные адреса Москвы/Санкт-Петербурга, неподтверждённые центральные20-км городские зоны без адресной идентичности и южная рамка безUIDоставлены отдельно. Это консервативный фильтр области референса, не полные официальные границы федеральных городов. Более точное адресное совпадениеНПимеет приоритет над грубым федеральным адресом. Все записи сохранены в длинном каталоге; внешний поднабор также вынесен в `places_external_geography.parquet`. Точная ранее карантинированная координатаПриозёрного не используется для пространственного связывания; строкаНПостаётся вwide.

## Типы и единицы

Исходные `taxonomy`, `basic_category`, название, адреса, источники, версии,confidenceиoperating_statusсохранены. Рабочие14групп:school,preschool,other_education,hospital,healthcare,veterinary,pharmacy,bank,atm,post_office,postal_collection_point,market,retail_store,food_service. Известные иные категории имеют `outside_requested_functions`, отсутствующая классификация — `unknown_999`, код999. Неизвестность не стирается и не превращается в отсутствие объекта.

ДляФАП/школ/рынков/Ozon/Wildberries имеются **отдельные признаки названия** `name_signal_*`; это не независимое подтверждение типа и не входит автоматически в основное функциональное разнообразие. Например, неизвестная категория с названиемФАПостаётсяunknown999ссигналом названия. Неподтверждённое присутствиеOzonне названо официальным реестромПВЗ.

Фактическая проверка пересечений выявила важную зависимость: **59249записей сWildberriesвназвании имеютtaxonomy `shopping`** и потому попадают в broadretail_store. При совместном скрининге это может дать одномуПВЗдве формальные функции — розничную и получения товаров. Исходный класс сохранён; требуется отдельная чувствительность розницы безWB/Ozon-nameлибо объединение торгово-логистических функций. Таблица `lexical_category_overlap.csv` позволяет проверить числа. Ozon-nameвстречается также у медицинских и иных организаций; само совпадение имени не доказываетПВЗ. ФАП-названий по основной кириллической маске всего3,сдобавлениемLatinFAP —4;это неполнота распознавания и источника,не оценка числаФАП России.

Счётчики имеют форму `places_{baseline|conditional|nearest_candidate}_{group}_count`. `all_categories_count` сохраняет все опубликованные записи. Основные функциональные и лексические счётчики исключают явно `permanently_closed` и confidence0; закрытый объект остаётся в каталоге и отдельном статусном счётчике. Отсутствующий статус остаётся `unknown`; это не подтверждённая текущая работа. Фактические статусы всех648242записей: **26open,648214unknown,2permanently_closed**. Оба закрытых относятся к retail_store;один conditional,другой внеосевой. Единственныйconfidence0 — второй,Monki,все3UIDпусты:он уже не участвовал в положительных признаках. Добавление явного будущего codeguardне изменило бинарные результаты; протокол `CONFIDENCE_ZERO_AUDIT.json`.

Confidenceсохранён без основного порога0.8; `source_quality_audit.csv` показывает диапазоны качества. Ниже0.5 находятся94574записи,ниже0.8 —426322,не менее0.95 —28326. По первичной документации это провайдерский показатель существования,а не текущей работы;распределения разных провайдеров не обязательно сопоставимы. Пороговые варианты — чувствительность,не независимая валидация и не повод объявить остальные объекты отсутствующими.

В длинной таблице `places_objects_and_crosswalk.parquet` сохранены `baseline_uid`, `conditional_uid`, `nearest_candidate_uid`, `nearest_uid_unaccepted`, `nearest_distance_km`, `linked_distance_km`, `source_geography_scope`, конфликтные и лексические поля. `linked_distance_km` относится к согласованномуUID;он может отличаться от ближайшего. Один исходныйGERSIDсохранён один раз;это не гарантирует отсутствия двух разныхGERSдля одного здания/организации.

Нет принятой записи означает отсутствие принятого свидетельства **в данном источнике и правиле**, не установленный ноль услуг. Ни capacity,ни внешняя аудитория,ни потоки,ни даты открытия этими POIне измерены. Современный выпуск не переносится на1989/2002/2010/2021.
