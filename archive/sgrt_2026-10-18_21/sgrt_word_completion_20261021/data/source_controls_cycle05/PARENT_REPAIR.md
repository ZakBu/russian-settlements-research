# Исправление уровня муниципального кода без изменения оси

После первой источниковой проверки выявлен отдельный дефект привязки: при расширении оси первые8цифр11-значного кода НП были названы кодом верхнего МО. В9245строках2021это другой, как правило нижний муниципальный уровень. BDMOкомпоненты здесь отбираются только для верхнего уровня; ошибочная по уровню привязка теряла доступные значения.

`repair_explicit_source_parent.py` независимо восстанавливает родителя из явных полей исходной таблицы переписи: регион + `mun_upper` строки НП → строка с типом `Муниципалитет верхнего уровня`. Для трёх НП Смоленской области с неоднозначным именем«Городской округ» требуется дополнительное точное совпадение восьмизначного нативного префикса с кодом типизированного родителя. Единственный несовпадающий ярлык«Город Иркутск»/«Городской округ Иркутск» связан только по точному нативному коду и субъекту. Нечётких именных совпадений нет.

Все155411принятых обычных НП2021 получили одного типизированного родителя. Для **всех2336верхних МО** сумма населения дочерних НП точно равна отдельно опубликованному итогуМО. Это контроль переписного источника, а не доказательство исторического равенства территорий2010↔2021.

Прежний код оси сохранён отдельной колонкой; ось не переписана. Новый нативный код родителя связывается с муниципальнымBDMOконтекстом только через явно существующий исходный мост2021. Необоснованный запасной переход к похожему/стабильному коду запрещён. Строгие фильтры исходных интервалов и единиц из первой проверки сохраняются.

|---|---:|---:|---:|---:|
|Жилищный ввод на жителя|135843|8191|1863|142171|
|Естественный прирост на1000|134666|8145|1863|140948|

Среди прежних кандидатов центров восстановлено27/34/35значений соответственно, удержано23в каждом компоненте. Там, где значение было и осталось известным, численное значение не изменилось ни разу. Это ремонт привязки и явный сценарий неопределённости, а не перерасчёт самих официальных числителей.

Главные выходы:

- `explicit2021_source_parent_bridge.parquet` —155411связей, оба кода, типизированные строки первичного перечня, правило разрешения.
- `repaired_source_parent_municipal_mass_controls.csv` —2336контролей.
- `parent_repaired_strict2021_settlement_context.parquet` —173527IDв прежнем порядке, три поля `context_*_parent_strict2021` и статусы.
- `parent_context_repair_before_after.parquet` —построчная сверка трёх компонентов.
- `parent_context_repair_receipt.json` —SHA,5существенных проверок, численности, пределы трактовки.

Жилищный ввод и демографические коэффициенты остаются **муниципальным контекстом**. Новая привязка не превращает их в собственные величины НП и не подтверждает границы исторических муниципалитетов. Исходный32-файловый snapshot `source_freeze_manifest.json` не менялся; дополнительный снимок этого исправления — `parent_repair_freeze_manifest.json`.
