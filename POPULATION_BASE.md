# Главная база населения: связанные переписи 2002 / 2010 / 2021

Это основной эмпирический результат проекта и исходная база для дальнейшего
исследования СГРТ. Принятый содержательный срез — **13 октября 2026 года**;
22 октября восстановлена его переносимая версия из опубликованных принятых
пакетов. Старые результаты районирования не входят в набор по умолчанию.

## Что готово

| Объект | Количество |
|---|---:|
| Исходные записи «НП — перепись» | 465 929 |
| Межгодовые компоненты принятого графа | 173 242 |
| Строгие полные ряды с тремя собственными численностями и точками | 142 765 |
| Исходные записи, зачтённые в рабочем слое | 431 948 |
| Принятые собственные представительские точки исходных записей | 447 373 |

Один компонент графа не обязательно равен неизменному физическому НП в одинаковых
границах. Число точек — число привязанных исходных записей, не уникальных координат.

| Перепись | Учтённое население | Контроль общей территории | Покрытие | Остаток |
|---|---:|---:|---:|---:|
| 2002 | 144 637 473 | 145 166 731 | 99,635414% | 529 258 |
| 2010 | 142 172 049 | 142 856 536 | 99,520857% | 684 487 |
| 2021 | 144 329 319 | 144 699 673 | 99,744053% | 370 354 |

**99,5%+ — доля населения в принятой рабочей пространственно-временной оси.**
Это не доля успешно сшитых НП, не оценка вероятности правильности связи и не
покрытие строгими полными рядами. Более широкая ось учитывает собственные
доступные годы, документированные исторические маршруты и федеральные территории
отдельно от обычных рядов. Федеральные территории учитываются один раз.
Знаменатели — зафиксированные контроли общей территории, не произвольный
современный национальный итог. Строгий слой — отдельные 142 765 полных рядов.

## Скачать и открыть

```bash
git clone --depth 1 --single-branch https://github.com/ZakBu/russian-settlements-research.git
cd russian-settlements-research
python scripts/research_data.py list
python scripts/research_data.py fetch
python scripts/research_data.py verify
python -m pip install -r requirements-handoff.txt
```

Команды без `--profile` получают **эту базу** (`core`). `population` и `current`
указывают на тот же принятый слой. Большие файлы лежат в отдельном
[релизе базы населения](https://github.com/ZakBu/russian-settlements-research/releases/tag/sgrt-census-population-20261022-v1),
каталог — `data/catalog.json`, краткий машиночитаемый паспорт —
`data/population_dataset.json`.

```python
import pyarrow.parquet as pq
long = pq.read_table('data/population/settlements_census_long.parquet')
wide = pq.read_table('data/population/settlements_census_wide.parquet')
full3 = pq.read_table('data/population/ordinary_full3.parquet')
```

| Файл | Единица строки | Назначение |
|---|---|---|
| `settlements_census_long.parquet` | Уникальный `source_record_id`: исходное наблюдение одного года | Все 465 929 записей, принятый межгодовой `root`, исходные и эффективные численности, точки, признаки и происхождение |
| `settlements_census_wide.parquet` | Один `root` | 173 242 компонента; поля с суффиксами `_2002`, `_2010`, `_2021`; недоступные годы остаются пустыми |
| `ordinary_full3.parquet` | Один строгий полный `root` | 142 765 рядов с тремя собственными численностями и принятыми точками |
| `federal_territories.csv` | Одна отдельная территория и перепись | Шесть территориальных записей для отдельного контроля, не обычные НП |
| `coverage.csv` | Перепись | Точные числители, знаменатели, проценты и остатки |
| `dataset.json` | Паспорт набора | Срез, проверки, происхождение и ограничения |

## Значение полей и правильные объединения

- `source_record_id` — первичный ключ исходного наблюдения; используйте его для
  присоединения источников, точек и функциональных данных. Название не является
  глобальным идентификатором. Чужие версии `root` без сверки не соединять.
- `root` — связь наблюдений в принятом графе этого среза. В длинной таблице пара
  `(root, census_year)` уникальна. Исторические включения не превращены в
  произвольное объединение всех предшественников и преемников.
- `population` — неизменённое исходное число; `effective_population` — выбранное
  число с отдельным принятым первичным overlay 2010. `population_overlay_applied`
  сообщает о применении overlay, а не о статистическом качестве.
- `latitude` / `longitude`, если присутствуют, — исходные поля;
  **`accepted_latitude` / `accepted_longitude`** — принятые собственные
  представительские точки. `accepted_point_present` отделяет принятую точку от
  отсутствующей. Точка может представлять исторический объект современным местом;
  это не наблюдение координат в день переписи.
- `coordinate_admission_status`, `coordinate_source_record_id`,
  `point_origin_file`, `point_origin_sha256`, `point_origin_locator`,
  `point_origin_kind`, `point_ledger_path` сохраняют квалификацию и происхождение
  точек. Сохранённые исходные абсолютные пути — provenance, а не обещание наличия
  файлов по этим путям у нового ассистента.
- `working_credit_present` — собственный UID входит в принятый рабочий союз.
  Чтобы воспроизвести числитель покрытия, по каждому году суммируйте
  `effective_population` **только** при этом признаке и добавьте соответствующие
  `territory_population` из отдельного федерального CSV ровно один раз.
- `finite_ordinary_full3_all_ownpoints` — исходная запись принадлежит строгому
  полному ряду. В широком слое этому соответствует `ordinary_full3`.
- `is_additive_settlement_record`, `population_scope`, `population_value_quality`,
  `oktmo`, `okato`, `source_file`, `source_path`, `source_sha256`, `source_locator`
  сохраняют исходную единицу учёта и происхождение. Отсутствующий исторический
  код остаётся неизвестным; код не доказывает неизменность границ.

Отсутствующее значение не заменять нулём. Не суммировать все исходные строки с
федеральными итогами и не складывать несколько версий одной численности. Для
демографической динамики предпочтителен строгий `ordinary_full3`; даже там
сопоставимость границ требует содержательной проверки. Рабочие 99,5% не следует
приписывать строгому подмножеству.

## Как восстановлено и проверено

[Манифест входов](research_context/population_source_manifest.json) закрепляет
177 файлов хешами SHA-256: stage71, накопленные принятые поправки, исправления
ошибочных компонентов/точек, итоговый реестр и отдельные территориальные оси.
Код — `scripts/maintenance/build_population_base.py`; он воспроизводит принятые
решения и прекращает работу при несовпадении хеша или контрольных показателей.

Проверены неизменность исходных полей, уникальность UID и пары root/год,
точное совпадение численностей, root и трёх ключевых признаков всех 431 948
зачтённых UID с опубликованным итоговым реестром, число собственных точек и
строгих рядов, все три числителя и знаменателя покрытия. Протокол публикации:
`research_context/reviews/population_base_validation_20261022.json`.

Это **восстановление принятых пакетов**, а не новая проверка каждого первичного
XLS/HTML. Исходный полный локальный экспорт имел SHA-256
`8be41d46b832310fc68bc48c715e71af87e5c525fc7e1c4d7264ce71931a623a`;
новые Parquet сериализованы заново и не объявляются побайтно тем же файлом.
Сохраняются все прежние ограничения качества источников и сопоставимости границ.

## Для всех ИИ-агентов

Эту базу берут за исходную агенты данных, демографии, медицины, образования,
коммерции, сельского хозяйства, литературы и проверки требований. Функциональные
слои присоединяются к ней с явным годом и ключом; их наличие не переписывает
переписную численность и не доказывает поток поездок.

Статус результатов различается:

1. **Принятое основание:** связанная база населения, описанная здесь.
2. **Исторические, отвергнутые как итоговая делимитация:** прежние модельные
   районы/типы СГРТ. Они доступны только через явные `legacy_model` (бывший
   `core`) и `legacy_model_full` (бывший `current`) либо `all`.
3. **Следующая научная работа:** функциональные массы, затухание, наблюдаемые
   связи, вложенная полицентричная иерархия, полная типология и карты.

Не объявлять готовую базу населения «ещё не сделанной» из-за незавершённости
СГРТ; не объявлять СГРТ готовыми из-за высокого покрытия базы населения.
Старые записки со словом default/stage71 отражают свою дату. Текущий выбор
определяют этот документ, `AGENTS.md`, `AI_START_HERE.md` и
`data/population_dataset.json`. Содержательный срез не обновляется молча;
для новых принятых данных нужны новая версия, проверки и запись в дневнике.
