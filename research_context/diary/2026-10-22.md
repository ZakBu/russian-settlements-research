## Каталог и упаковка данных

Источником служит опубликованный срез85aebaf. Найдены8919 путей структурированных данных общим логическим объёмом18275963965байт. После объединения одинаковых Git-объектов остаётся7638 объектов,15480782760байт. Идентичное содержимое хранится один раз. Исходные пути сохраняются в каталоге.

Предусмотрены профили core, current и all. Current соответствует структурированным данным последнего принятого вычислительного пакета; это не новая функциональная модель. Каталог не утверждает, что архивированы все внешние исходные публикации: условия и места их получения остаются в первичных реестрах. Полные чужие книги не копируются в переносимый набор.

Parquet сохраняются побайтно, чтобы не изменять значения, типы и доказательную цепочку. Для каждой таблицы извлекаются схема и число строк. CSV сжимаются; уже сжатые Parquet/NPZ/GZ не перепаковываются с потерями. ZIP хранят объекты по содержимому. План включает41часть меньше2ГиБ; исходные пути восстанавливаются скриптом.

Проверки: каждый исходный объект сверяется с Git SHA-1 и SHA-256; известные SHA-256 из финального манифеста дополнительно сопоставляются. После загрузки ZIP его размер и SHA-256 сверяются с серверными значениями GitHub. Downloader повторно проверяет ZIP и извлечённые объекты. Наличие каталога со статусом uploading не равно завершённой загрузке.

Прямая загрузка Releases из текущей среды вернула401Bad credentials на uploads.github.com, хотя запись Git/API работала. Для завершения используется GitHub Actions со штатным GITHUB_TOKEN, без запроса пользовательских ключей. Workflow вручную запускается из репозитория, упаковывает данные, проверяет загрузку, фиксирует окончательный каталог и дописывает дневник. До проверки завершения перенос не объявляется полным.
