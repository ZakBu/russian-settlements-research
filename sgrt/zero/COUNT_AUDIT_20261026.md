# Почему получилось только 197 групп

**Число 197 нельзя использовать как оценку количества местных систем с полным набором услуг. Проверка обнаружила две причины занижения: слишком узкое правило совпадения направлений и неполную привязку школ и магазинов к населённым пунктам. Есть конкретный пропуск алгоритма: название Питерской школы содержит село, район и область, но эти сведения не использованы для установления её НП.**

Проверены опубликованные направления и таблица центров от 25 октября, основанные на переписных НП 2021 года и разновременных сведениях об учреждениях. Направления и исходная база в этом аудите не менялись. Код пересчитывает счётчики независимо от готовой сводки и сверяет наличие трёх местных функций с таблицей центров. [Числа и SHA исходных файлов](../../research_context/analysis_snapshots/zero_centre_count_audit_20261026.json).

## Три разных условия дают три разных числа

| Условие в имеющихся данных | Центров |
|---|---:|
| Известное положительное население, целая допустимая запись НП; внутри этого НП привязаны школа, базовая медицина и продукты | 978 |
| То же, и есть хотя бы один внешний жилой участник по одной из трёх функций | 804 |
| То же, и хотя бы один и тот же внешний участник выбирает этот центр сразу по всем трём функциям | 197 |

У 607 из 804 центров не выполняется именно последнее условие. Они не должны исчезать из рассмотрения только потому, что направления за разными услугами не совпали у одной и той же деревни. Ещё у 174 из 978 центров не установлены внешние участники по базовым функциям. Наличие полного набора само по себе не доказывает собственную зону притяжения.

До проверки целостности записи и положительного населения полный местный набор отмечен у 986 исходных точек; после неё — у 978. Это отдельный небольшой отсев, не главная причина малого числа.

## Сама привязка учреждений неполна

По всем 153 803 исходным точкам школьная функция привязана к 2 418 НП, базовая медицина — к 36 856, продуктовая торговля — к 5 103. Это не число всех учреждений России и не оценка числа НП, где они реально есть.

Проблема видна уже в городах и пгт: среди 2 249 целых допустимых записей с положительным населением школьная функция привязана только к 615, полный набор — к 501. Для 1 934 таких городских записей с населением меньше 50 тыс. человек школа привязана к 416, полный набор — к 306. Значит, неполнота затрагивает не только маленькие деревни.

Из 125 558 допущенных школьных направлений в 109 628 случаях известна физическая площадка, но её НП не установлен. Для продуктовых направлений таких случаев 80 314 из 103 081. Эти направления сохранены в данных, однако не могут подтвердить общий НП-центр по действующему правилу. Неизвестная принадлежность не означает отсутствия учреждения.

### Конкретный пропуск: Питерка

У школьного объекта `osm:way:743189713` в исходном `official_name` записано:

> Муниципальное общеобразовательное учреждение «Средняя общеобразовательная школа с. Питерка Питерского района Саратовской области».

При этом `source_address_locality` и `source_record_id` пусты, статус — неустановленная принадлежность НП. Из-за этого в строке села Питерка школьное предложение внутри НП не установлено, хотя модель выбирает эту школьную площадку с автомобильным временем 0,86 минуты. Близость сама по себе не доказывает принадлежность; здесь дополнительное свидетельство — буквальное полное название с указанием территории. [Исходные поля и происхождение](../../research_context/analysis_snapshots/zero_centre_piterka_identity_error_20261026.json).

У Новоузенска также выбрана школьная площадка с неизвестным НП, 2,19 автомобильной минуты. В её рассмотренной карточке есть только `amenity=school`; этот случай требует дополнительного адресного или официального источника. Автоматически приписывать её городу по ближайшей точке нельзя. [Строки направлений для Саратова, Энгельса, Новоузенска и села Питерка](centre_count_examples_20261026.csv).

## Что исправлять

Нужно извлекать явную местность из полных названий и официальных адресов, сверять тип НП, район и регион, разрешать одноимённые поселения; отдельно использовать проверяемые границы населённых пунктов. Затем заново посчитать местное предложение и направления. Для объектов без достаточного свидетельства оставить неизвестную принадлежность, а не назначать ближайший НП.

Сам полный набор в центре, внешнее обслуживание по отдельным функциям и совпадение всех направлений должны оставаться разными показателями. Требование совпадения не является необходимым условием существования местной системы.

Ожидание 2–3 тыс. полнофункциональных систем — гипотеза для проверки, не доказанный ориентир и не параметр настройки. По числу городов и сёл нельзя вывести количество центров с внешним окружением. Но нынешние 197 также не опровергают это ожидание: они получены при неполных привязках и дополнительном жёстком условии.

Для повторения после восстановления опубликованного комплекта и старой переписной оси:

```bash
python scripts/sgrt_zero/audit_centre_count.py \
  --scenario NEW/analysis/scenarios/daily_20_school30_wb \
  --reference BUNDLE/context/analysis_reference.parquet --output AUDIT
```

Существующий выпуск сохраняется как воспроизводимый расчёт. Системы не объявлены подтверждёнными реальными поездками; следующая версия требует исправления привязок, а не подбора желаемого числа групп.
