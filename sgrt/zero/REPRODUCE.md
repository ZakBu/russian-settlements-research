# Как повторить расчёт

**После содержательного аудита:** точный контроль v1 повторяйте его сохранённым кодом (коммит `6f9718906772f3f7740a44a56f9ef22fea3cae38`). Текущая ветка содержит новые правила допуска и демографические поля; это уже изменённый метод. [Найденные ошибки и команды аудита](ERROR_AUDIT_20261025.md).

`scripts/sgrt_zero/reproduce.py` повторяет выделение локальных групп по ближайшим повседневным услугам, пять вариантов границ, четыре последовательных объединения по более редким функциям и карты. Он сохраняет различие между модельным направлением поездки и наблюдённым потоком. Число верхних ступеней и единственность Москвы не подгоняются под ожидаемый результат.

Есть три способа работы. Полный расчёт получает закреплённые источники и заново ищет ближайших поставщиков услуг по дорожному графу. Компактный расчёт берёт сохранённые дорожные направления и заново строит группы и карты. Упаковка сохраняет уже рассчитанные таблицы; она сама по себе не подтверждает повторение расчёта.

## Полный расчёт

Понадобятся Python 3.11+, зависимости из `requirements-sgrt-zero.txt`, сеть для скачивания GitHub Releases и свободное место для исходных архивов, дорожного графа, таблиц и результатов. Старые каталоги требуют около 3,3 ГБ скачивания с федеральным медицинским архивом; рабочие копии занимают больше. Граф и его координаты повторно не включаются в новый архив результатов.

```bash
python -m pip install -r requirements-sgrt-zero.txt
python scripts/sgrt_zero/reproduce.py --plan
python scripts/sgrt_zero/reproduce.py \
  --workdir /workspace/sgrt-zero-repeat \
  --source-commit FULL_40_CHARACTER_GIT_COMMIT \
  --source-manifest-sha256 PUBLISHED_64_CHARACTER_MANIFEST_SHA256
```

SHA исходного манифеста публикуется вместе с релизом источников `sgrt-zero-inputs-20261025-v1`. Значение по умолчанию уже закреплено в коде: `d9c8617dadbed91d92cf0cf1e139af67fddf5e9c33c7c50f09cd577c0c664ddc`. Без корректного закрепления полный режим откажется работать. Он проверяет SHA архива, каждого файла и согласованность внутреннего и внешнего манифестов. Дата снимка берётся из манифеста; текущие часы не меняют датировку данных. Живые API ПВЗ в этом режиме не опрашиваются.

Полная последовательность заложена в код: контекст трёх федеральных городов → медицина и исключение учреждений закрытого обслуживания → образование → торговля и нормализация публичных снимков Wildberries, Яндекс Маркета и 5Post → поиск ближайших поставщиков → пять вариантов нулевого уровня → четыре объединения → проверки → атлас → архив. Отдельный закреплённый релиз `sgrt-zero-medical-inputs-20261025-v1` содержит весь реестр медицинских организаций Саратовской области за 2021 год: PDF 2 151 654 байта, SHA `f8fca17deb75e86b711b3c18a15d909e7341b9baa53b3d93ae6f383835de5c6c`. Код извлекает все страницы, сопоставляет явные адреса и добавляет допустимые предложения как исторические приближения. Работа учреждений в 2026 году этим не подтверждается. Строгий вариант без этого дополнения сохраняется в рабочем каталоге `health/strict_control`; в основной архив включается объединённый вариант с явными годами и признаками исторического источника.

Для основного медицинского расчёта добавлен федеральный справочник НСИ ОМС на 23 октября 2026 года: закреплённый релиз `sgrt-zero-federal-medical-inputs-20261025-v1`, архив `SpravNSI_20261023.zip`, 93 455 460 байт, SHA `e7bab4fa92ba0273faf18d6bfb97c368c3fd0b66290c3b2a82d82bc47ff6db42`. Код отдельно читает организации, подразделения, виды помощи и фактические адреса оказания помощи; юридический адрес не становится адресом обслуживания. Сохраняются текущие записи и полная история, проверяются интервалы действия. Адреса связываются с переписными НП по явным реквизитам, без подстановки ближайшего НП.

Федеральные предложения без координат учреждения используют представительную точку НП: `physical_coordinates_observed=False`. Это отдельное пространственное допущение. Вид помощи и детский контингент сохраняются; наличие стационара не объявляется доказательством универсально подходящей больницы. Все страницы исходного саратовского PDF и федеральный архив сохраняются, многогигабайтные временные XML восстанавливаются из архива при полном повторении и не входят в пакет.

Продуктовое обслуживание в полном основном расчёте объединяет два положительных источника: магазины OSM 2021 года и свежие сведения о продуктовом магазине по месту размещения ПВЗ 5Post. Выбирается целая строка с ближайшим допустимым поставщиком, сохраняются её год, точность координат и качество. Это одна функция; сведения о местах размещения ПВЗ не объявляются полным реестром магазинов. Выбор этого варианта записывается в `analysis_options.json`. Наличие диагностической таблицы само по себе не меняет прежний контрольный расчёт.

Место работы и сельское хозяйство сохраняются как самостоятельные контекстные признаки; число организаций не объявляется числом рабочих мест.

Старая связанная переписная база, официальные медицинские и дошкольные таблицы берутся из закреплённых прежних каталогов. Это воспроизводит расчёт поверх сохранённых данных; оно не означает повторного сбора всех реестров с их первичных сайтов. Годы источников различаются и сохраняются в таблицах. Историческая торговля OSM 2021 года не становится наблюдением 2026 года. Дополнительные направления к 5Post и магазинам, указанным как места размещения ПВЗ, сохраняются отдельно; они не увеличивают число независимых функций основного расчёта.

## Компактный пересчёт

Скачайте `zero_catalog.json` из `sgrt-zero-systems-20261025-v1` и восстановите именованные файлы командой ниже. Архив `zero-data.zip` хранит объекты по контрольным суммам; обычная распаковка ZIP не восстанавливает структуру исследования. `research_data.py` скачает архив и восстановит каталог `sgrt/zero20261025`. Внутри есть `checksums.json`, исходные и нормализованные таблицы, дорожные направления и копия кода в `reproduction/`.

```bash
python scripts/research_data.py fetch --catalog /workspace/zero_catalog.json \
  --profile core --dest /workspace/unpacked --cache /workspace/zero-download-cache
python scripts/sgrt_zero/reproduce.py \
  --from-bundle /workspace/unpacked/sgrt/zero20261025 \
  --workdir /workspace/sgrt-zero-compact-repeat \
  --source-commit FULL_40_CHARACTER_GIT_COMMIT
```

Сначала проверяются контрольные суммы всех файлов. Старые группы и карты не копируются как новые результаты: они пересчитываются. Дорожный поиск не повторяется. Режим подходит для проверки правил допуска, группировки, типологии и последовательных объединений, но не для проверки самой дорожной сети.

На другой машине можно запустить сохранённый код из каталога `reproduction/`: в нём есть необходимые скрипты, каталоги прежних данных, зависимости и научный контекст.

## Подготовленные локальные данные и упаковка

```bash
python scripts/sgrt_zero/reproduce.py --prepared \
  --workdir /workspace/sgrt-zero --source-commit FULL_40_CHARACTER_GIT_COMMIT
python scripts/sgrt_zero/reproduce.py --package-only \
  --workdir /workspace/sgrt-zero --source-commit FULL_40_CHARACTER_GIT_COMMIT
```

Первый вариант пересчитывает анализ из уже подготовленных источников и дорожных таблиц. Второй только упаковывает полный набор. До удаления прежней локальной сборки код проверяет наличие всех пяти вариантов группировки, верхних объединений и атласа. Исправленные восемь медицинских классов заменяют прежние классы в едином представлении, исходные файлы остаются неизменны. При наличии подготовленной версии `commerce/federal_context` используются именно её окончательные таблицы.

Результат находится в `WORKDIR/built`: `zero-data.zip`, `zero_catalog.json`, `zero_atlas.pdf`, `preview.png`. Архив сохраняет подробные Parquet-таблицы, точные источники из записанного происхождения данных, контрольные суммы, код и контекст исследования. Он исключает дорожные массивы, отвергнутые промежуточные расчёты и технические дубликаты. `logical_source_roles.json` показывает, какой исходный файл и SHA использованы для каждой логической таблицы.

Внутри архива `RESULT_README.md` создаётся после вычислений из фактических итоговых таблиц. Это описание завершённого запуска. Тексты в `reproduction/research_context/` сохраняют состояние на момент исходного коммита кода: если он был сделан перед долгим расчётом, там ещё может стоять отметка о запуске. Оба состояния различаются явно; ни одно не подменяет историю исследования.

Сводка `hierarchy_readout/` сравнивает все 15 рассчитанных разделений, размеры групп и именованные примеры. `functional_complexity/` описывает известные функции внутри уже сформированных групп и сохраняет неравенство полноты источников. Эти описания не изменяют состав групп и не присваивают Москве или другим центрам заранее заданный ранг.

## Что проверяется автоматически

Во всех пяти вариантах сохраняются 153 803 начала: 153 800 обычных НП и три городских контекста без дополнительного зачёта населения. Каждый НП входит ровно в одну группу; каждая группа имеет тип. Каждая следующая ступень состоит из целых групп предыдущей. Проверяется арифметика дорожного времени, уникальность начал и отсутствие скрытого ограничения дальности в исходных направлениях. Отдельные временны́е ограничения применяются позже, при выделении локальных связей.

Эти проверки выявляют потерю данных и нарушение алгоритма. Они не доказывают реальные поездки, полноту учреждений или достоверность границ. Неизвестная принадлежность объекта к НП сохраняется как неизвестная; ближайший НП не подставляется вместо установленного адреса.

## Проверка скачанного комплекта его собственным кодом

Для проверки именно опубликованного расчёта используйте сохранённый внутри комплекта код. Скрипт ниже сначала сравнивает его Python-файлы с исходным коммитом, затем проверяет все контрольные суммы и заново строит группы, верхние объединения и карты. Исходные дорожные направления читаются, а не копируются как новые группировки. Новый архив не создаётся.

Если репозиторий клонирован с `--depth 1`, сначала получите исходный коммит выпуска:

```bash
git fetch --depth 1 origin 6f9718906772f3f7740a44a56f9ef22fea3cae38
OPENBLAS_NUM_THREADS=1 python scripts/sgrt_zero/verify_public.py \
  --bundle ../sgrt-zero-data/sgrt/zero20261025 \
  --workdir ../sgrt-zero-public-repeat \
  --source-commit 6f9718906772f3f7740a44a56f9ef22fea3cae38 \
  --output ../sgrt-zero-public-comparison.json
```

Рабочий каталог должен быть пустым и находиться на той же файловой системе, что и скачанные данные: неизменяемые входы связываются жёсткими ссылками для экономии места. Их контрольные суммы проверяются до и после расчёта. Итоговый JSON перечисляет все сравнения таблиц и карт, побайтовые совпадения и отдельно случаи численного допуска `1e-12`. Это повторение правил группировки; полный пересчёт дорог из сети выполняется отдельным полным режимом выше.
