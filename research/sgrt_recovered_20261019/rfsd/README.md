# RFSD: восстановленный и повторно выполненный этап

`primary2010/` — новое вычисление по восстановленным колоночным исходникам2016/2021 и новой замороженной геометрии GIS2010. Модель идентифицирована SHA в FINISHED.json. Организация связывается с ближайшим наблюдаемым населённым пунктом и его центром; максимальная дистанция1/5/10км задаёт экспериментальную адресную локализацию. UNASSIGNED не превращается в финансовый центр. Юридический адрес не является местом производства, рабочим местом или наблюдением поездки.

Baseline: INN известен, eligible=1, filed=1, articulated=1, outlier=0, выручка известна и неотрицательна. Strict добавляет house-levelгеокодирование и imputed=0. Нет замены неизвестной выручки нулём; активы/прибыль остаются неизвестными, когда все значения в группе отсутствуют. Один отсутствующий INN в каждом исходном году явно учтён и исключён; уникальность INN внутри года проверена.

Финансовые единицы — тысячи номинальных рублей (повторно проверенный авторский источник financial_unit_source.json); дефлирование не выполняется. Финансовая отчётность не измеряет занятость, полноценную экономику территории или бюджетную сервисную инфраструктуру. Филиалы без отдельного юрлица не локализуются. Государственные/финансовые/религиозные неeligible организации и неотчитавшиеся не представлены выбранной выборкой. Отсутствие наблюдений не доказывает отсутствие деятельности.

`financial_observations.*` содержит шесть режимов локализации и отбора адресных наблюдений. `sector_sensitivity.*` сохраняет все сектора, включая UNKNOWN в знаменателях. `center_economic_witness.*` требует, чтобы ближайший НП сам был центром (nearestNP.id==center_id); это свидетельство адресной экономической активности центра, а не обслуживания его сельского окружения. `verify_projection.py` проверяет сохранение счетов и выручки в каждой зоне/году/режиме, включение строгой выборки и вложенность дистанционных порогов. Запись атомарна: временный файл→чтение обратно→проверка→rename; FINISHED.json фиксирует хеши.

`functional/` — описательная финансовая специализация: основная мера — число организаций, доля сектора>=0.20, LQ>=1.25, N_зоны>=5. Возможны несколько специализаций; доминирующий сектор выбирается по доле с детерминированным разрешением равенства. Нет подходящего сектора и недостаточная выборка — отдельные состояния. Сопоставляются число фирм/выручка, baseline/strict и1/5/10км. UNKNOWN не объявляется специализацией. Эти признаки не использованы для формирования массы центров или настройки границ.

`reference2002_recovered/` — восемь лет2017–2020/2022–2025 из восстановленного облачного архива. ZIP SHA/CRC, происхождение и все суммы повторно проверены в новом запуске audit_reference_archive.py (reference_archive_verification.json). Это сохранённая справочная геометрия2002, а не новая модель2010. Историческое получение исходников не выдаётся за повторный download. Workercloud_reference_missing.py иcloud_recovery_workflow.yml выполняют семь недостающих лет2011–2016/2021 заново: удалённая схема byte-range до скачивания рядов, SHA закреплённого файла, колоночное чтение50kстрок и удаление сырого файла. Сеть передаёт полный сжатый файл, что отдельно обозначено.

Повтор нового первичного присоединения:

```bash
python research/sgrt_recovered_20261019/rfsd/project_finances.py --cache PATH_TO_ENRICHMENT --membership research/sgrt_recovered_20261019/model/nearest_membership.parquet --out replay_rfsd/primary2010
python research/sgrt_recovered_20261019/rfsd/verify_projection.py --projection replay_rfsd/primary2010
python research/sgrt_recovered_20261019/rfsd/classify_functional.py --projection replay_rfsd/primary2010
```

Необходимо numpy/pandas/scipy/pyarrow; путь к исходникам передаётся явно. Все итоги справочного ряда и первичной модели должны соединяться только в своей собственной геометрии; перенос сумм2002 по совпавшему center_id в2010 запрещён.
