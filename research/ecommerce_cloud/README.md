# Продолжение общероссийского исследования WB/Ozon

## Продолжение: новые данные и проверенный результат

Периферийный след получения товаров расширяется одновременно с частой демографической концентрацией центра. Это совместное наблюдение, а не идентифицированное ослабление центра под действием платформ.

- Новая панель: 564 средних центра в 67 регионах, 2023–2025 годы. Доля населения центра выросла у 435; в 386 случаях росла при сокращении обеих частей.
- Получены три полных официальных реестра ОКТМО около дат наблюдений. При одинаковых полных кодах и названиях остаются 416 центров, рост доли у 320; при дополнительном метадатаскрине — 291 и 233. Перечень не доказывает постоянства координатных границ.
- Шесть исторических выходов ATP/WB 2023–2024: у 563 из 1 152 средних центров с записью на обе даты расширился положительный след населённого окружения. Декабрьский API рассматривается отдельно; это не открытия и не измерение потоков.
- В торговой панели после контроля полных составов C/S остаются 150 центров: 74 увеличили долю магазинов минимум на 1 п.п., 23 потеряли; медиана +0,932 п.п. Это муниципальный запас, не оборот, поездки или все физические закрытия.
- В восьми проверенных полных исторических инвентарях ATP российского Ozon не найдено. Это ограничение конкретного источника; национальная сопоставимая история Ozon остаётся незакрытой.

## Быстрый запуск

Из корня репозитория, Linux, Python 3.11:

```bash
python3 -m venv .venv-ecommerce
. .venv-ecommerce/bin/activate
python -m pip install -r research/ecommerce_cloud/requirements.txt
python research/ecommerce_cloud/fetch_bundle.py
python research/ecommerce_cloud/check_bundle.py
python research/ecommerce_cloud/run_checks.py
```

`check_bundle.py` проверяет наличие и SHA256 всех переданных файлов. `run_checks.py` запускает три существующие проверки расчётов последовательно, с остановкой при ошибке. Они не удостоверяют причинную идентификацию. Установку Python-пакетов в чистом Linux здесь ещё не проверяли; локальные проверки используют уже установленную среду. Не переносите старый `/tmp/...` PYTHONPATH.

Облако должно открыть ветку `codex/ecommerce-settlement-cloud-20261025` в `ZakBu/russian-settlements-research`. Ветка основана на `origin/main`, доступной при переносе; её SHA записан в манифесте. Локальная исследовательская ветка имела три коммита `0d58775`, `3e2a365`, `1ebc646`; их содержимое перенесено как материалы исследования, не как переписывание истории main.

## Что передано

Рабочие материалы лежат в `work/sources/research/ecommerce_settlement_20261024/`. Сохранено расположение файлов, которое ожидают скрипты. В версионированном GitHub Release доступны национальные таблицы, переписные входы, исходные тела WB/Ozon, официальные ОКТМО, извлечённый полный раздел БДПМО, адресные торговые реестры и необходимые внешние таблицы. `data_manifest.json` перечисляет переданные файлы и хеши, а также исключения.

Полные тексты научных публикаций не переопубликованы; библиография, карточки доказательств, DOI, URL и заметки о доступности сохранены. Архив данных хранится в 13 частях; fetch_bundle.py параллельно получает их, проверяет каждую часть и собранный архив. Дублирующий ZIP БДПМО исключён: полученный из него Parquet включён. Если нужен аудит ZIP, повторно получите его по закреплённому URL и проверьте SHA256 из исходного манифеста. Не считать такой аудит уже выполненным в облаке. Некоторые старые приобретательные скрипты и исходные манифесты ссылаются на исключённые оригиналы: это не обязательные входы трёх расчётных проверок.

Вложенные `.gitignore` исторически исключали входы из Git. Для облака они восстанавливаются загрузчиком из Release. Не удаляйте их как якобы ненужные промежуточные данные без проверки зависимостей.
