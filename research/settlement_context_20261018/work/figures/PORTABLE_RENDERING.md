# Переносимое воспроизведение научных рисунков

`build_figures.py` — замороженный исходный рендерер, использованный для опубликованных изображений. Его исходные пути описывают среду авторского расчёта и сами по себе не являются переносимым CLI. `render_figures_portable.py` — отдельная оболочка: она меняет **только назначение путей в памяти**, не изменяет исходный рендерер, не обучает модели, не читает первичный gzip и отказывается перезаписывать существующий выходной каталог. SHA оболочки, исходного renderer и входов включаются в новый receipt.

## Что нужно подготовить

`--staging-root` указывает на папку с сохранёнными исследовательскими результатами:

| Путь внутри staging-root | Назначение |
|---|---|
| `geo/features.csv.gz` | Все реальные репрезентативные координаты/UID 2010 и population_2010 для рисунка3. Нужны только четыре столбца, но текущий интерфейс читает исходный feature artifact. |
| `e1/development/split_manifest.csv.gz` | UID, holdout, fold, block_id; используется для карты и аудита состава. |
| `e1/development/result.json` | Разведочный E1 и его условный интервал. |
| `e2/development/result.json` | Разведочный E2 и его условный интервал. |
| `e3/development/result.json` | Разведочный E3 и его условный интервал. |
| `e2/illustrative_pairs_preoutcome.csv` | Пара, выбранная исключительно по X до исходов. |
| `e3/regional_curves.csv` | Геометрические региональные кривые и контрпример знаменателя. |
| `statistics/calibration/run_v1/results.json` | Синтетическая диагностика покрытия, не реальная калибровка эффектов. |
| `final/evaluation.json` | Все18 заранее фиксированных финальных конфигураций и conditional intervals. |

`--audit-root` указывает на фактический `data_audit`, внутри которого нужны:

- `evidence/data_contract.json`;
- `evidence/zero_three_way_patterns.csv`;
- `evidence/population_value_quality_2010.csv`.

Рендерер и оболочку следует положить рядом. Если это невозможно, передать `--renderer-script /path/to/build_figures.py`.

## Команды

Сначала проверка без записи файлов и без построения графиков:

```bash
python render_figures_portable.py \
  --staging-root /absolute/path/archived_research_staging \
  --audit-root /absolute/path/data_audit \
  --output /absolute/path/new_figure_export \
  --check-only
```

Затем та же команда без `--check-only`. Каталог output должен ещё не существовать. Создаются восемь комплектов PNG300/JPG300/SVG/CSV, подписи, contact sheet, manifest и portable_render_receipt. Исходная авторская visual-QA не переносится на другой рендер: новый contact sheet требуется посмотреть отдельно. Библиотеки: Python3, numpy, pandas, matplotlib, Pillow, pyproj; точное окружение исходного расчёта фиксируется общим environment manifest. Изменения версий шрифтов/рендерера могут менять пиксели без изменения чисел, поэтому гарантируется вычислительная прослеживаемость, а не побитовое равенство PNG на произвольной машине.

## Чего недостаточно

Выход только `reproduce.py` с финальными predictions/evaluation не содержит development, E3, аудит и все координаты карты. Он **недостаточен** для полного комплекта восьми иллюстраций. Не следует молча заменять отсутствующие результаты примерными или синтетическими значениями.

Опубликованные числовые CSV рисунков удобны для проверки чисел и собственных альтернативных изображений, но не являются полным восстановительным набором исходной карты. В частности, `03_spatial_split.csv` содержит центры тяжести точек блоков, а опубликованная карта показывает **все** координаты НП; изображение из одних центроидов было бы другим рисунком. `02_quality_status.csv` отдельно хранит укрупнённый состав качества. Текстовые/CSV поля некоторых синтетических результатов также не заменяют исходный генератор.

Поэтому полное воспроизведение требует восстановить перечисленные небольшие JSON/CSV и feature artifact из исследовательского архива либо заново получить их профильными скриптами с теми же SHA/параметрами. Это явная зависимость сохранённых артефактов, а не обещание, что произвольный final-only output восстановит всю историю разведки. Первичные переписные массивы и полные тексты литературы оболочка не копирует и не перераспределяет.

## Проверка оболочки и ошибка записи

Первый тест прямой записи в новый workspace output обнаружил усечение двух PNG до одинаковых 131216 байт; PIL отказался загрузить их. Исходный авторский комплект не изменялся и повторно загрузился корректно. Причина сбоя файловой среды не установлена. Оболочка теперь сначала полностью рендерит в локальный временный каталог, проверяет загрузку всех восьми PNG и переносит файлы через SHA-проверку и атомарный rename. Второй тест прошёл; восемь PNG побитово совпали с исходным авторским комплектом в данном окружении. Машинный receipt — `portable_wrapper_test.json`. Это проверка нового пути рендера без повторного обучения моделей.
