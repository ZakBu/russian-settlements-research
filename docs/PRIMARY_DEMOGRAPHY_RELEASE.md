# Отдельный выпуск демографии основного окружения

Выпуск `sgrt-primary-demography-20261027-v1` воспроизводит четыре полные научные таблицы и карту всех 28 512 зарегистрированных центров. Он не заменяет старый выпуск демографии пересекающихся окружений и не устанавливает причинные типы Word.

## Исходные данные

Берутся ровно четыре файла из существующих неизменяемых каталогов:

| Каталог | Вход |
|---|---|
| `data/common_systems_catalog_20261027.json` | `results/level0/units.parquet` и `results/level0/memberships.parquet` |
| `data/zero_catalog_20261025.json` | `context/analysis_reference.parquet` |
| `data/centre_demography_catalog_20261026.json` | `readout/centre_demographic_classes.parquet` старых окружений |

Загрузка использует существующий проверяемый HTTP Range механизм. Проверяются размер и SHA-256 каждого распакованного файла; при полном скачивании дополнительно проверяется весь исходный архив. В новый ZIP включаются все четыре входа, полные результаты, методические тексты, каталоги, код, зависимости и контроль. Размещение файлов и сжатие не меняют население.

## Контроль воспроизведения

Локальный законченный расчёт сохранён в `/workspace/sgrt-primary-demography-three-intervals-20261027`. Его контроль — `research_context/analysis_snapshots/primary_demography_control_20261027.json`. Контроль учитывает все строки со всеми столбцами четырёх Parquet, кратность строк, оба режима качества, полное научное резюме и все строки карты. Числовые значения таблиц сравниваются с восемью десятичными знаками существующим общим методом контроля. Сведения об источниках и SHA кода также входят в резюме.

Команда фиксации локального контроля, без упаковки ZIP:

```bash
python scripts/sgrt_zero/cloud_primary_demography.py \
  --control-results /path/to/completed/readout \
  --units /path/to/common/results/level0/units.parquet \
  --control-output research_context/analysis_snapshots/primary_demography_control_20261027.json \
  --export-map /path/to/new/primary-centre-demography.csv
```

Контроль не генерируется заново внутри облачного расчёта как ожидаемый результат: вычисленный в Actions вариант сравнивается с уже закоммиченным независимым локальным контролем. Код первичной демографии переиспользует неизменённый опубликованный компонентный метод. Четвёртый вход обязательно используется для сравнения прежнего и основного составов по тем же идентификаторам центров.

## Карта в существующем редакторе

`primary-centre-demography.csv` содержит `id`, `name`, `lat`, `lon`, `value`, идентификатор НП и точные описательные статусы за три отрезка. Эти поля совместимы с адаптером `csv-points` существующего редактора. В подписи точки написаны оба направления, а исходный код сочетания сохранён в `descriptive_primary_type_2002_2021`. Основной показ — принятые значения, не только первичные наблюдения.

Категории `value`:

1. Центр и сельское основное окружение убывают.
2. Обе части растут.
3. Разнонаправленная динамика или точное равенство одной из частей.
4. Недостаточно сопоставимых данных о центре или сельском окружении.
5. В основном распределении нет внешних сельских участников.

Пятая категория имеет приоритет над неизвестной историей центра: отсутствие сельского основного окружения остаётся видимым. Неизвестный тип внешнего НП не считается доказанным отсутствием сельского окружения. Размер или цвет точки не означает доказанность СГРТ и не устанавливает исторические потоки.

## Подготовка черновика в Actions

Ручной workflow `.github/workflows/publish-primary-demography.yml` запускается только после коммита всех файлов отдельной ветки. Он устанавливает `requirements-common-systems.txt`, выполняет проверки, загружает четыре входа, пересчитывает результат, сверяет полный контроль и создаёт ZIP на диске GitHub Actions. Локальная упаковка большого ZIP не требуется.

```bash
python scripts/sgrt_zero/cloud_primary_demography.py \
  --source-commit "$GITHUB_SHA" --workdir "$RUNNER_TEMP/primary-demography"
python scripts/sgrt_zero/cloud_primary_demography.py \
  --source-commit "$GITHUB_SHA" --draft-built "$RUNNER_TEMP/primary-demography/built"
```

Рабочий каталог должен быть новым и находиться вне Git. Исходный коммит должен точно совпадать с чистым checkout. Выпуск и тег с таким именем должны отсутствовать; существующий черновик не перезаписывается. Внешний и вложенный манифесты, все SHA членов ZIP, четыре входа по каталогам, код воспроизведения и полный CSV проверяются до создания черновика. После загрузки сверяются точный целевой коммит, статус `draft` и имена, размеры и серверные SHA всех трёх активов: ZIP, манифест, CSV.

Workflow не раскрывает выпуск публично. Основной агент отдельно проверяет конкретный созданный черновик, полный контроль, все файлы и карту; только после этой проверки может быть выполнено отдельное действие публикации. В коде этого выпуска нет автоматического `draft=false` или команды публикации существующего черновика.
