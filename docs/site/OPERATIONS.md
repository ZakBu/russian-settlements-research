# Сборка и публикация портала

Сайт статический: Astro создаёт страницы, React/MapLibre/ECharts отвечают за взаимодействие. Сервер и API-ключ ИИ для сайта не нужны. Исследовательские агенты работают в своей среде и заканчивают задачу публикационным пакетом.

## Локальный запуск

```bash
python -m pip install -r requirements-site.txt
npm --prefix web ci
python scripts/site_content.py sync-state --json
python scripts/site_content.py validate --json
python scripts/build_site_data.py
npm --prefix web run dev
```

По умолчанию приложение доступно на http://localhost:4173/. Сборка данных проверяет научные каталоги и SHA; большие данные остаются в игнорируемом кеше. Повтор без сети: `python scripts/build_site_data.py --offline`.

## Проверки

```bash
python -m unittest discover -s tests -p 'test_site_*.py'
python -m unittest discover -s tests -p 'test_build_site_data.py'
npm --prefix web run check
PUBLIC_BASE_PATH=/russian-settlements-research/ npm --prefix web run build
```

Браузерные сценарии: `npm --prefix web test`. Если сервер ещё не работает, тесты запускают статический preview. Для проверки подпапки задайте `PUBLIC_BASE_PATH=/russian-settlements-research/`; для внешнего работающего сервера — `SITE_TEST_URL` с полным адресом и завершающим `/`. Браузер берётся из `/usr/bin/chromium`, если установлен; иначе выполните `npx --prefix web playwright install --with-deps chromium`. Проверяются поиск, фильтры, контекст исследования, темы, утренние обновления, источники, карта, подключаемый слой, мобильная вёрстка и доступность.

## GitHub Pages

Один раз включите **Settings → Pages → Source: GitHub Actions**. Это административная настройка: доступ интеграции к коду сам по себе не гарантирует право включать Pages.

`site-ci.yml` запускается на тематических PR и изменениях main, синхронизирует состояние, проверяет контент, формирует веб-данные и сборку. PR получает скачиваемый предпросмотр и браузерные артефакты. Main публикуется через официальный Pages deploy; дополнительно workflow можно запустить вручную.

```bash
gh workflow run site-ci.yml --ref main
gh run list --workflow site-ci.yml --limit 5
```

`site-automerge.yml` сливает только прошедшие проверку content-only PR из этого репозитория от владельца или явно указанных `SITE_TRUSTED_ACTORS`. Изменения программ и workflows не входят в автослияние. Проверяется именно SHA головы PR; после token-merge публикация запускается явно. Событие, созданное `GITHUB_TOKEN`, нельзя считать надёжным способом запуска следующего workflow.

Если сборка не прошла, прежний опубликованный сайт остаётся доступен. Причина и исходники сохраняются в Actions/PR. Для отката используйте проверенную предыдущую версию кода и повторный запуск публикации. Научные ZIP и каталоги не перезаписываются.

## Данные и размеры

- Веб-данные и шрифты доставляются с того же сайта; браузер не читает научные ZIP.
- Полная карта и детали загружаются отдельно от облегчённых превью главной и атласа.
- Экспорт останавливается выше целевых 350 MiB. Репозиторий не хранит генерируемые GeoJSON, Parquet, PDF и web/dist.
- Сетка Terrae 2026.10 закреплена по срезу OSM 28.09.2026: 83 региона и 2 297 районов/округов плюс две служебные территории. Исходные GPKG и обычное преобразование GDAL в GeoJSON сохранены в выпуске `atlas-boundaries-20261026-v1`; SHA находятся в `data/site_assets.json`. Сетка источника не подменяет переписную основу из 85 субъектов. Сводки считаются по готовому уровню medium (около 150 м); для экрана применяется прежнее упрощение 0,002° и округление координат. Незаметные в масштабе страны островки опускаются только в декоративном контуре превью, не в слоях и сводках. Старый источник geoBoundaries 2017 остаётся в истории Git; дата границ не подменяется датой сборки.
- Подложка Esri — справочная, с атрибуцией. При её недоступности остаются локальные исследовательские слои. Она не служит источником научной принадлежности НП.
- Три исходных снимка интерфейса — узкие исключения политики как требования дизайна. Научные бинарные результаты остаются в Releases.

## Быстрая загрузка карт

Обзорные карты главной, каталога и статьи генерируются `npm run prebuild` из закреплённых данных в SVG. Те же файлы используются в карточках и полных материалах; имена содержат хеш содержимого. Они не требуют JavaScript, React или загрузки географических JSON в браузере. `npm run dev` также создаёт эти изображения; сначала должны быть подготовлены данные командой `python scripts/build_site_data.py`. Изображения и их реестр находятся в игнорируемой папке `web/public/data`.

Интерактивная карта использует точное словарное представление всех переписных точек `settlements.compact.json`; имена, ID, координаты, нули и пропуски сохраняются. Слои отображаются независимо по мере получения, районы подгружаются при включении, поиске или прямой ссылке. Отдельная геометрия для экрана округлена до пяти десятичных знаков; сводки продолжают рассчитываться по исходным контурам. Ошибка или задержка слоя районов не блокирует население. Неизменившиеся источники не передаются MapLibre повторно для кластеризации.

Мини-карты используют готовое поведение D3 Zoom, без MapLibre и его источников данных. `prebuild` дополнительно создаёт небольшой именованный по хешу файл `mini-map-labels-*.json`: проекция, русское имя, численность 2021 года и изменение из той же пространственной выборки. Файл загружается только при первом приближении и переиспользуется всеми мини-картами страницы. Первые поля `settlements-preview.json` сохраняют прежний смысл; после координат и изменения добавлены имя и численность для подписей. У крупных видимых карт интерактивный SVG готовится после первого отображения; маленькие активируются при наведении, фокусе или кнопкой. Новый материал автоматически получает эти возможности через существующий компонент.

## Word как производное представление публикации

Сборка сайта дополнительно создаёт `exports/*.docx`: файл каждой доступной статьи и сборник каждого исследования, с единой нумерацией рисунков и источников внутри файла. Это генерируемое представление материалов сайта, не новая версия научных данных. DOCX входят в артефакт GitHub Pages и доступны по кнопкам статей; в Git они не записываются. Для отдельной закреплённой научной публикации используется обычный версионированный выпуск.

Нужны Pandoc, Chromium (или Google Chrome), Node 22+ и `requirements-site.txt` с python-docx. `npm --prefix web run build` сначала строит Astro, затем готовый Playwright снимает реальные рисунки, а Pandoc создаёт редактируемый Word с общим профилем. Карточка-ссылка на карту не снимается как научный рисунок. Крупные таблицы остаются таблицами, раскрытия раскрываются, внутренние вики-ссылки между включёнными главами становятся переходами внутри Word. Оглавление — нативное поле Word с видимыми ссылками на разделы; его страницы обновляются при открытии/обновлении полей.

```bash
python -m pip install -r requirements-site.txt
npm --prefix web ci
# Установите Pandoc и Chromium системным пакетным менеджером, если их ещё нет.
npm --prefix web run build
python scripts/site_content.py export --materials map-reading-guide,model-and-observation --format docx --output /tmp/research.docx
```

Профиль вуза можно передать через `--reference-doc /path/template.docx`. Он применяется к Word; браузерная типографика остаётся прежней. Проверка реального DOCX через Pandoc находится в `tests/test_word_export.py`, браузерные проверки подписей, ссылок и скачивания — в `web/tests/gost.spec.ts`.

В GitHub Actions Pandoc 3.1.11.1 устанавливается готовым `r-lib/actions/setup-pandoc`, закреплённым на коммит. Сборка не обновляет все системные apt-репозитории: это устраняет задержки сторонних зеркал и сохраняет одну версию конвертера с локальными проверками.

## Адреса единой библиотеки

Каталог — `/materials/`, представления — `?view=list`, `?view=cards`, `?view=graph`; отбор хранится в query (`q`, `research`, повторяющийся `tag`, `kind`, `format`, `territory`, `currency`, `sort`, `collection`). Локальное окружение графа — `focus=ID&depth=1` или `2`. Старые `/atlas/` и `/knowledge/` рендерят тот же каталог; при включённом JavaScript адрес канонизируется с сохранением запроса. Без JavaScript статьи и каталог остаются доступны.

Лента — `/updates/`; `?unread=1` включает непросмотренное. Отметки в `atlas-read-versions` относятся к хешу содержимого, иллюстраций и версий наборов данных, без тегов и оформления библиографии. Они сохраняются только в браузере пользователя, без синхронизации устройств и сервера. Для отладки сбрасывайте этот ключ в тестовом браузере, а не меняйте дату научной публикации.

## Дерево материалов

`parentId` — ID родительской статьи в том же исследовании, без ограничения числа уровней; `order` задаёт порядок соседей, затем применяется русский алфавит и ID. Поля необязательны. Дерево использует стандартные раскрытия браузера, сохраняет открытые ветви в сессии. `/materials/?within=ID` отбирает родителя и всех потомков, сохраняя другие условия и представление. Физические пути и URL не зависят от иерархии. Word исследования перечисляет статьи в порядке обхода дерева, родителя перед потомками; явный пользовательский список для экспорта сохраняет заданную последовательность.

## Подложка, детали и скорость

`map-basemap.ts` подключает существующую OpenFreeMap Liberty без замены стиля исследования. Источник — видимые векторные тайлы; максимум приближения 19, кеш ограничен 96 тайлами. Дороги и здания появляются по минимальному масштабу, здания с z13, первого доступного масштаба источника. Стиль имеет таймаут и отмену; недоступность подложки не блокирует локальные данные. DOM-подписи НП служат резервом при отказе внешнего контекста. Смена темы применяется и после позднего ответа подложки.

Первый национальный экран читает `settlements.overview.json`; полная `settlements.compact.json` загружается при поиске, масштабе z7+ или сохранённом выборе НП. Файлы создаются из одного набора с одинаковыми ID и пропусками, обзор никогда не перезаписывает уже полученную полную коллекцию. Полигональные сводки заранее считаются по полной основе, а не по прореженным точкам.

Контуры городов берутся из принятого инвентаря существующего выпуска, а не из живого геокодера. Сборщик извлекает закреплённый Parquet по диапазонам ZIP с проверкой SHA, кэширует его и создаёт 256 небольших файлов геометрии по ID. Офлайн-сборка использует тот же проверенный кэш. Круговые буферы вокруг точек и контуры округов вместо населённых пунктов не применяются.
