# Контракт контента атласа, версия 1

Контент декларативный. ID — `lowercase-kebab`. Каждое поле выполняет научную или навигационную роль. Произвольные HTML, MDX, JavaScript, CSS, функции и настройки ECharts не допускаются.

## Реестры

`web/content/research.json` — массив объектов:

```text
id, title, description, status, summary, nextStep, order
```

`web/content/datasets.json` — массив источников:

```text
id, title, release, sourceCommit, url, sha256?, period, scope, limitations[]
```

Версия источника закрепляется явно; ссылка ведёт на существующий выпуск или точный файл коммита. `limitations` описывает область применимости, пропуски и ограничения интерпретации. Поле `sha256`, если есть, содержит 64 шестнадцатеричных символа.

`web/content/materials/ID.json`:

```text
id, researchId, title, summary, kind, topic, territory, period,
publishedAt, updatedAt, visibility, evidence, currency, sourceCommit,
sources: [{title,url}], datasetIds: [ID], visualIds: [ID], body,
supersedes?: ID, featured?: boolean, tags?: [ID], parentId?: ID, order?: number
```

- `kind`: finding / method / note / correction.
- `visibility`: draft / published / archived — состояние публикации.
- `evidence`: observation / calculation / model / hypothesis / method — основание утверждений.
- `currency`: current / known-issues / superseded — актуальность.
- `publishedAt`, `updatedAt`: ISO дата или дата-время; человекочитаемые даты показываются по Москве.
- `body`: Markdown с готовыми блоками документов: заголовки H2/H3 с автоматическим оглавлением и якорями, цитаты, списки, таблицы, иллюстрации, сноски, `[!NOTE]` / `[!WARNING]`, `:::details`, `[[material-id|подпись]]` и `:::visual visual-id`. Синтаксис и пример — в [инструкции автора](AUTHORING.md#разметка-документа). Выполнение кода и произвольный HTML запрещены. Вики-ссылки указывают на существующий документ, публичный материал не ссылается на черновик. ID встроенной визуализации должен входить в `visualIds`, её набор — в `datasetIds`; один блок визуализации встраивается один раз.

Публикация требует заполненной территории, периода, коммита, источников и текста. Публикационный статус не доказывает научную правильность. Исследовательская модель может быть опубликована с явным названием и ограничениями.

## Единая библиотека и темы

Публичный каталог `/materials/` объединяет результаты, методы, заметки и исправления. «Список», «Карточки» и «Связи» — представления одних записей; отдельные копии для прежних «Атласа» и «Знаний» не создаются. Адрес статьи `/materials/ID/` сохраняется.

`web/content/tags.json` — небольшой словарь `{id, label, aliases?: [string]}`. `label` — русское название темы; `aliases` — слова для поиска, а не дополнительные теги. В необязательном поле материала `tags` перечисляют уникальные ID словаря, например `"tags": ["census", "data-quality"]`. Неизвестный ID или повтор блокирует валидацию. Обычно достаточно 2–4 тем. Это редакционная рекомендация, не требование к научному результату. Новые теги добавляют, когда существующий словарь не описывает самостоятельную тему; синонимы дополняют `aliases`.

`kind`, `researchId`, `evidence` и `currency` остаются самостоятельными признаками. Они не заменяются тегами. `topic`, `territory` и `period` сохраняют точное человекочитаемое пояснение. Фильтр территории группирует явно названные места вместе с родителями; неизвестная территория не назначается по догадке из случайного упоминания в тексте.

Форматы вычисляются из зарегистрированных визуализаций и Markdown: карта, график, таблица, иллюстрация. `service-links` означает переход к карте, а не встроенную карту. Статическая картографическая иллюстрация распознаётся по содержательному alt-тексту и ближайшему заголовку: называйте её картой и описывайте показанные территории. Если тип изображения не установлен, оно остаётся иллюстрацией; тему `cartography` нельзя использовать как доказательство наличия карты.

Новые автоматические снимки состояния без `tags` остаются допустимыми и получают тему хода исследования в каталоге. Отсутствие тегов у старой записи не мешает поиску: каталог использует короткий fallback по её `topic`. Обычный агент выбирает темы при публикации, без ручного изменения навигации и CSS.

## Вложенные статьи

У материала может быть необязательный `parentId` — ID существующей родительской статьи того же `researchId`. Поле указывает на запись, а не на URL и не на путь к файлу. Без `parentId` материал находится в корне своего исследования. Родитель сам может быть вложен в другой документ: поддерживаются четыре, пять и больше уровней без установленного предела глубины.

```json
{
  "id": "census-source-comparability",
  "researchId": "population",
  "parentId": "population-comparability",
  "order": 20
}
```

Это фрагмент полей иерархии; для публикации остаются обязательными обычные текст, контекст и источники. Необязательное конечное число `order` задаёт порядок среди детей одного родителя: меньшие значения идут раньше. Значение не является номером главы или рисунка; допустимы дробные значения для вставки между соседями. Если порядок не задан, интерфейс использует обычную сортировку. Поле `order` можно задавать и корневым материалам. Не используйте `null`, строки, логические значения или бесконечность.

Валидация проверяет всё дерево, даже при `validate --material ID`: родитель существует, отличается от ребёнка, принадлежит тому же исследованию, цепочка не замыкается. У опубликованного ребёнка каждый родитель в цепочке также должен быть опубликован. Если родитель стал черновиком или архивом, сначала согласованно перенесите либо измените публикационный статус его дочерних статей. Черновик можно готовить внутри черновика или архива; это не делает его доступным публике.

Вложенность — навигационное отношение, не научная ссылка и не тип доказательства. Она не заменяет `supersedes`, теги и ссылки на методы. Перенос в другую ветку и изменение `order` не меняют ID, постоянный адрес `/materials/ID/`, якоря разделов или научную версию материала. Менять `updatedAt` лишь ради перестановки в дереве не нужно. Старые статьи без новых полей остаются допустимыми.

## Визуализации

`web/content/visuals/ID.json`:

```text
id, template, title, caption, datasetId, palette, unit,
categories?: [string], series?: [{name,values:[number|null]}],
data?: array, mapState?: object, limitations?: [string]
```

Шаблоны: `census-trend`, `bars`, `comparison`, `scatter`, `table`, `settlement-map`, `service-links`.

Палитры: `population-change`, `categorical`, `service-type`, `blue`. Единица обязательна, например `человек`, `%`, `км`, `ед.`. Число категорий совпадает с числом значений каждой серии. Пропущенное наблюдение — `null`, а не ноль и не строка.

`mapState`: `research`, `layers`, `period`, необязательные `selection`, `lat`, `lng`, `zoom`. Состояние используется ссылкой «Исследовать на карте». Функциональная связь должна иметь указание основания; модельное направление не подписывается как наблюдаемая поездка.

Поле `data` применяется к таблице/точечной диаграмме по поддерживаемой реализации компонента. Новый формат данных сначала согласуется в инженерном PR с примером, рендерером и проверкой; нельзя передавать код под видом данных.

## Адреса и версии

Дополнительные слои карты: `web/content/layers/ID.json` с полями `id`, `researchId`, `title`, `description`, `datasetId`, `adapter`, `geometry`, `fields`, `palette`, `unit`, `period`, `evidence`, `visibility`. Адаптеры `geojson`, `csv-points`, `csv-settlement`; CSV поддерживает только точки. Для источника обязательны pinned HTTPS и SHA-256. Подробности и исполняемый пример — [LAYERS.md](LAYERS.md). В `mapState.layers` разрешены базовые ID и ID опубликованных дополнительных слоёв.

- Материал: `/materials/ID/`.
- Исследование: `/research/ID/`.
- Самостоятельная визуализация для экспорта: `/visuals/ID/`.
- Опубликованный префикс GitHub Pages: `/russian-settlements-research/`; настройка `PUBLIC_BASE_PATH`. Локальный сервер по умолчанию работает от `/`; CLI использует ту же переменную окружения.

Стабильный ID сохраняет ссылку после исправления. Источник в опубликованном материале обновляют содержательно, вместе с выводами и ограничениями. Нельзя подменить ZIP старого научного выпуска новыми данными. Для новых принятых данных нужен новый выпуск; контрольная сумма проверяется существующим загрузчиком.

## Библиографические сведения и нумерация

У записи `sources[]` материала и записи набора данных допустимы фактические поля `authors` (строка или массив), `year`, `publisher`, `place`, `journal`, `volume`, `issue`, `pages`, `doi`, `accessed` (действительная дата обращения `YYYY-MM-DD`) и `referenceId` (ID из `references/sources.json`). Неизвестные сведения опускаются; дата пересборки не становится датой обращения. `title` и `url` остаются обязательными.

Синтаксис `[@source:1]` ссылается на первый источник материала, `[@data:census-population]` — на зарегистрированный набор из `datasetIds`, `[@HUFF1964]` — на литературу, `[@fig:population-map]` — на рисунок по ID. Номер назначается в порядке использования, не хранится в контенте. Указатель `[@source:1, с. 34]` сохраняет проверенную локализацию. Неизвестная ссылка, отсутствующий набор или ссылка на карточку-переход как на рисунок блокирует публикацию. Профиль, подписи, заимствованные изображения и сборники описаны в [ГОСТ-гайде](GOST.md).
