# Вход для нового ИИ-ассистента

**Главная готовая база — [связанные НП за 2002/2010/2021](POPULATION_BASE.md).** Начинай научную работу с неё, а не с прежних модельных районов. Принятый слой имеет рабочее покрытие населения 99,635414% / 99,520857% / 99,744053%; 142 765 строгих полных рядов считаются отдельно. `core` по умолчанию, `population` и `current` скачивают именно эту базу. Старый core перемещён в `legacy_model`, старый current — в `legacy_model_full`.

Это продолжающееся исследование сельско-городских районов тяготения России. Пользователь хочет передавать репозиторий между ассистентами без потери контекста, данных и истории решений.

## Получи данные

Данные находятся в GitHub Releases **этого же репозитория**, без внешнего аккаунта или отдельного облака. Исторические Parquet сохранены побайтно. Главная база населения логически восстановлена из закреплённых принятых пакетов и сериализована заново; её новые хеши и проверки указаны в паспорте. Каталог связывает содержимое с путями и ZIP. Все пути и версии доступны через [data/catalog.json](data/catalog.json).

Для новой рабочей среды сначала получить актуальное дерево без старых больших объектов истории:

```bash
git clone --depth 1 --single-branch https://github.com/ZakBu/russian-settlements-research.git
cd russian-settlements-research
```

Затем из корня клона:

```bash
python scripts/research_data.py list --profile core
python scripts/research_data.py fetch --profile core
python scripts/research_data.py verify --profile core
```

Профили core / population / current получают принятую базу населения. legacy_model / legacy_model_full — явно архивные старые расчёты, отвергнутые как итоговая делимитация. all содержит также историю. Поля, ключи, правила NULL и трактовка99,5% описаны в POPULATION_BASE.md. Сначала посмотри объём командой list. В related_releases каталога перечислены ранее опубликованные вспомогательные наборы и исходные архивы, включая baseline; они доступны по готовым ссылкам без дублирования. Для чтения Parquet установи проверенную зависимость: `python -m pip install -r requirements-handoff.txt` (PyArrow26.0.0); сам загрузчик использует только стандартную библиотеку Python. Схемы и количество строк также записаны в каталоге.

Загрузчик обрабатывает ZIP по одному и по умолчанию удаляет архив и временный объект после восстановления файлов: для all не нужны одновременно все ZIP, все распакованные объекты и все копии. Флаг --keep-archives сохраняет ZIP-кэш при достаточном месте. Скачанные данные и .research-cache не коммить заново. Если файла нет в каталоге, сначала проверь подробные манифесты и историю; не придумывай значения и не объявляй набор полным. Непопавшие в Git локальные файлы, исчезнувшие при сбое прежней среды, не восстановлены.

## Продолжи работу

Зафиксируй в новом дневнике, что прочитано и какие данные проверены. Затем выполняй следующий научный шаг из current_state.json. Не начинай заново весь проект и не считай формальный отчёт или одобрение агента доказательством реальных связей. После работы оставь подробную запись для следующего ассистента.

## Выборочные данные и схемы

Необязательно скачивать весь профиль. Можно найти нужную функцию и получить только выбранные пути:

```bash
python scripts/research_data.py list --profile all --match '*medical*' --show-files --show-schema
python scripts/research_data.py fetch --profile all --match '*medical*'
```

--match сопоставляется с исходным путём; несколько --match объединяются по OR. Размер скачивания определяется ZIP, содержащими выбранные объекты. Схемы и число строк доступны в каталоге без скачивания самих таблиц.

### Особые исторические файлы

`data/source_special_files.json` сохраняет проверенные исходные Git-режимы и хеши
четырёх символических ссылок и одного AppleDouble-файла macOS. Две ссылки
разрешаются в существующие таблицы: загрузчик создаёт независимые копии таблиц.
Ещё две уже в исходном опубликованном снимке указывали на отсутствующий каталог
`cycle06_network2021_access_v2_seventh_extension`: их содержимое сохраняется как
метаданные, `usable_as_table=false`. Подстановка похожих таблиц не выполняется.
AppleDouble также является метаданными. Все пять относятся только к `all`;
основные профили `core` и `current` не затронуты. Исходные объекты ZIP побайтны;
разрешённые ссылки при материализации становятся копиями целевых таблиц.

Если `all` был загружен до исправления каталога, два разрешённых пути могут
содержать прежний текст ссылки. `fetch` остановится с `Existing file differs`.
Сверьте SHA-256 именно этих файлов с `original_sha256` в
`data/source_special_files.json`, перенесите совпавшие файлы в отдельный каталог
резервной копии и повторите `fetch`. Любое другое несовпадение требует отдельного
разбора. `verify` подтверждает контрольные суммы; читаемость Parquet проверяется
отдельно и отражена в каталоге.
