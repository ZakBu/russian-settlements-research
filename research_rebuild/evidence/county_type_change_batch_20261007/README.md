Candidate packet only. No accepted statuses or accepted graph files are written here. The pinned stage-2 working-state loader includes the 678 bracketed-2010 edges and 677 transferred points. The pinned baseline in simulation_receipt.json is the baseline used for these gains; later independently accepted cases may change marginal gains.

454 previously distinct component unions pass exact normalized settlement name + region + explicit source county, unique per year when type is ignored. County normalization is imported from apply_unique_county_name_bridge_20261007.county_key. Every proposed union joins components with no repeated census year and has an already accepted component point. Existing accepted endpoint/component points must agree within 5 km of the donor; both endpoint points, when present, are also within 5 km. Native source coordinates, conflicting alternatives, shared same-year points, event IDs/native codes, part rows and administrative aggregates block candidates. Per-year uniqueness is computed before excluding event rows. Population controls processing order only.

All 454 edges have a possible_type_change flag. This is disagreement in the selected source classifications, not proof of a dated legal reclassification. Raw labels and selected classifications remain separately visible. Exact county/name uniqueness and an accepted point support the proposed continuity; type change alone is never identity evidence. Provider identifiers and independent historical coordinates are not asserted.

450 new point uses are proposed as representative spatial continuity over these identity candidates. Points are never represented as historical measurements. Protected 2010 population values, district fields and all source data remain untouched. Simulated full-chain population gains are 80,685 (2002), 80,510 (2010), and 95,249 (2021).
