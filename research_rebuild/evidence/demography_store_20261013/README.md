# Демографический контекст БДМО «Если быть точным», версия 20260928

`store.py` создаёт действующее хранилище DuckDB с 16 отдельными представлениями `dataset_Y…`, объединённым `demographic_context` и интерфейсом `municipal_context`. Исходные крупные Parquet используются напрямую; CSV преобразуются DuckDB без pandas; XLSX читаются openpyxl в read_only/data_only и пакетами Arrow по 10 000 строк. Физические пустые строки XLSX пропускаются; пустое значение показателя сохраняется как NULL, не как ноль. Все исходные столбцы, включая административные коды, историю, начало/конец периода кода, пол, возраст, направление миграции, национальность и тип места жительства, сохраняются. Представления приводят исходные поля к VARCHAR для совместимости и отдельно дают `value_numeric`, `source_year`. Числовое значение не заменяет исходное поле.

Всего прочитано **192 756 041 строка**, из них **192 680 111 непустых числовых значений** (это количество строк со значением, а не число уникальных фактов) и **75 930 неизвестных**.

Полные данные и база: `/workspace/scratch/demography-store-20261013/`. Каталог загрузок: соседний `tochno_catalog_20261013`. `store_receipts.json` содержит URL, член архива, исходные и полученные SHA256, число фактических строк/непустых числовых значений, схемы и годы каждой части. Range-источники сохраняют CRC, диапазоны байтов и ETag: полный ZIP для них не скачан и его SHA256 не заявляется. Число строк Parquet-метаданных не является числом доступных значений: используйте `indicator_inventory.csv` и `data_profile.csv`, полученные запросами по настоящим значениям. Поле `source_row_0based` — физический индекс в Parquet; для преобразованного XLSX это индекс непустой строки после заголовка, а не координата Excel.

В архивах выбирается ровно одна полная версия каждого показателя: верхнеуровневый Parquet, если он есть, иначе верхнеуровневый CSV. Дублирующие региональные и годовые представления полного набора не добавляются. Для шести больших показателей используются только выбранные каталогом взаимоисключающие полные/годовые части.

`candidate_key_duplicates.csv` характеризует повторы ключа код–год–уровень–единица–период–измерения и отдельно конфликтующие значения. Строки не удаляются. `arithmetic_checks.json` проверяет рождённые минус умершие против естественного прироста и прибывшие минус выбывшие против миграционного прироста только для уникальных совпадающих ключей с одинаковыми измерениями и периодом кода. Несопоставимые или неоднозначные записи не исправляются автоматически.

Проверка повторов завершена для всех 16 показателей (`duplicate_scan_status.json`). Арифметика проверена для естественного баланса за 2008–2023 годы: 218 расхождений; для миграционного баланса за 2008–2015 годы: 15 487 расхождений. Это флаги качества исходных значений, сохранённых без исправления. Миграционные годы 2016–2024 в этой диагностике не проверены; они доступны в хранилище и точных профилях. `arithmetic_checks.json` явно разделяет проверенные и непроверенные годы.

Конкретный запрос НП `2021:data_allsettlements_anon_156_v20251217.parquet:parquet:10` вернул реальные муниципальные строки всех 16 показателей; квитанция `np_query_smoke.json` фиксирует число строк, исходные годы и коды по каждому показателю. Это контекст муниципалитетов, а не значения НП.


`192 680 111` — число строк с исходным числовым значением, **не число уникальных или достоверных фактов**. Дубли и противоречия сохранены. `source_value_numeric` отделён от `usable_value`: последний NULL для NaN/Inf, отрицательных значений несальдовых показателей и численности населения/детей свыше 300 млн. Отрицательные естественный прирост, его коэффициент и миграционное сальдо допускаются. `value_status` объясняет механический фильтр. Он не подтверждает достоверность остальных значений или уникальность ключа. Национальность с отрицательным значением считалась бы ошибкой до подтверждения правила подавления источником; такое правило не выдумывается.

Обнаружены 10 отрицательных коэффициентов рождаемости, 11 отрицательных значений сельского возрастного населения и одно отрицательное число выбывших (−226) и городское возрастное значение 30 879 747 684 (Георгиевск, женщины, «Всего», 2018). Они не исправлены и не превращены в ноль. Полные исходные строки с тегом причины и локатором: `numeric_anomalies.csv`; числовая проверка по каждому показателю: `numeric_validity.csv`. NaN/Inf в 16 показателях не найдены. После 23 проверенных доменных ошибок остаётся 192 680 088 числовых строк в `usable_value`, **включая дубли**; `usable_data_profile.csv` показывает эти числа по годам и уровням.

Муниципальный контекст не является населением НП. `municipality_code8` — исходный муниципальный ОКТМО из 8 цифр; 7 цифр дополняются начальным нулём при сохранении исходной строки. Другие длины, включая 11-значные коды НП, не обрезаются и дают NULL; `oktmo_stable` не используется для объединения разных территорий. `source_admin_history_present` отмечает наличие истории; переименование и смена типа сами по себе не означают изменение границ. `explicit_boundary_change_requires_review` выделяет текст объединения/разделения. Изменение состава территории требует отдельного временного доказательства; обычные строки не блокируются из-за непустой истории.

Воспроизведение:

```bash
python store.py --build
python store.py --numeric-audit
python store.py --validate
python store.py --bridge /workspace/scratch/tochno-np-attach-20261013/native_np_municipality_bridge.csv.gz --np-id SOURCE_RECORD_ID
```

Последний запрос сначала выбирает один НП в мосте, затем присоединяет муниципальные факты по коду и уровню. Он не создаёт огромную таблицу НП × демографические строки. Результат `np_context.jsonl` содержит `context_only=true`, исходные годы и метаданные моста: его версия справочника, опорный 2021 год и отсутствие утверждения исторического членства. Значения муниципалитета не распределяются по НП и не подменяют переписные/текущие значения НП. Совпадение кода с мостом 2021 года само по себе не доказывает принадлежность НП муниципалитету во все годы ряда.

Представления базы ссылаются на абсолютные пути текущего рабочего пространства. Если пакет содержит 66 уже подготовленных Parquet, `--source-root` автоматически выбирает их по именам из `store_receipts.json` и сверяет `store_sha256`, сохраняя оригинальный источник/хеш и не требуя ZIP/XLSX. После переноса архива запустите `python store.py --build --source-root /путь/к/исходникам --scratch /путь/к/хранилищу --catalog /путь/к/tochno_catalog_20261013`; исходные байты сверяются с SHA256 каталога, повторная загрузка не нужна.

Зависимости: Python 3, duckdb, pyarrow, openpyxl. Источник: Росстат БДМО в обработке «Если быть точным»; содержание и определения показателей относятся к оригинальному источнику. Описание и ограничения источника сохраняются в исходном каталоге; эта реализация не добавляет собственную оценку качества или точности Росстата.
