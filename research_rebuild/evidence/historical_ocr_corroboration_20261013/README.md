# Очередь проверки OCR с числовым сопоставлением

Ограниченный проход по 3055 строкам существующего OCR сопоставил 80 буквальных собственных названий с текущими проверенными QID/UID-привязками. Получены 35 строк очереди для 35 НП с точным равенством хотя бы одного из четырёх исходных числовых полей и вторичного P1082 того же года (1979/1989). Из них 19 также имеют точную квалификацию нормализованным названием региона; 16 требуют проверки исторического регионального имени. Исторические переименования и границы регионов не угадывались.

`numeric_corroboration_review_queue.csv` сохраняет исходные OCR-поля, страницу PDF, сторону скана, ключ строки, хэши PDF/TSV, текущий собственный UID/root/QID и каждый числовой матч с GUID/датой/точностью вторичного утверждения. Поля 1979/1989 «наличное»/«постоянное» сравниваются независимо. Удаляются только краевые табличные вертикальные черты и пробелы вокруг целого числа; OCR-цифры не исправляются. Название сравнивается после NFKC, регистра, е/ё, пробелов и удаления табличных точек/вертикальных черт; похожесть и исторические именные алиасы не применяются.

Очередь сначала ставит квалифицированные регионом и многократно численно совпавшие строки, затем более крупные значения. Среди первых: Каменск-Уральский (стр.109, левая сторона), Балашиха (стр.92, правая), Белогорск (стр.119, правая), Артемовский и Богданович (стр.109, левая), Алексеевка (стр.100, левая), Томилино (стр.93, левая).

Все строки остаются `candidate_numeric_corroboration_only_OCR_NOT_ADMITTED`. Равенство чисел не проверяет первичную транскрипцию, тип населения, границы или независимость источника: вторичная ссылка может использовать тот же первичный сборник. Тип «наличное/постоянное» из P1082 не выводится. Никакие OCR-значения, новые исторические идентичности, нули или прирост покрытия не приняты. Нужна сверка конкретного скана и его заголовков. Исходные 9045 наблюдений не пересобирались, PDF не скачивался, Git не изменялся.

Повторный проход после исправления исходного CSV-парсера (QUOTE_NONE для тех же 82 TSV): SHA-256 входа `5e81b3f4c9b064f7c386a056b8cfa332945cc75acc4b2735dd4d717296505715`. Пересчитана только очередь; вторичные Parquet не изменены.
